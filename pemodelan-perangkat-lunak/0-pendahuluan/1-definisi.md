# ✅ **Definisi Software Engineering & Modeling**

## 1. **Apa itu Software Engineering (Rekayasa Perangkat Lunak)?**

**Software Engineering** atau **Rekayasa Perangkat Lunak (RPL)** adalah:

> *"Suatu disiplin ilmu teknik yang berfokus pada proses sistematis, terukur, dan terstruktur dalam pengembangan, pengoperasian, dan pemeliharaan perangkat lunak."*

### Penjelasan Sederhana:

Bayangkan kamu ingin membangun rumah. Kamu tidak bisa hanya membawa semen dan bata tanpa rencana. Kamu butuh:

* **Arsitek**: membuat rancangan rumah (analisis & desain)
* **Insinyur**: memastikan bangunan kokoh (coding & testing)
* **Mandor**: memastikan proyek selesai tepat waktu dan sesuai anggaran (manajemen proyek)

Itu semua adalah bagian dari *rekayasa*, dan jika rumahnya diganti jadi **software**, maka kita bicara tentang **rekayasa perangkat lunak**.

---

## Tujuan Software Engineering

* Menghasilkan **perangkat lunak berkualitas**: fungsional, handal, aman, dan mudah digunakan.
* Proyek dapat diselesaikan dengan **waktu dan biaya yang efisien**.
* Memastikan **pemeliharaan** jangka panjang terhadap perangkat lunak.
* Mengurangi risiko **kegagalan proyek**.

---

## Karakteristik Utama Software Engineering:

| Karakteristik     | Penjelasan                                                                     |
| ----------------- | ------------------------------------------------------------------------------ |
| **Systematic**    | Proses pengembangan software dilakukan secara terstruktur, bukan asal-asalan.  |
| **Disciplined**   | Mengikuti praktik terbaik dan standar industri.                                |
| **Quantifiable**  | Bisa diukur dari segi kualitas, performa, waktu, dan biaya.                    |
| **Collaborative** | Melibatkan tim lintas peran: analis, programmer, tester, project manager, dll. |

---

## 2. Apa itu Modeling dalam Software Engineering?

### Definisi:

**Modeling** adalah proses membuat **representasi abstrak** dari sistem perangkat lunak. Representasi ini bisa berupa:

* Diagram alur
* Diagram kelas
* Use case
* Diagram ERD
* DFD, dsb.

Modeling penting karena:

> *"Kamu tidak bisa membangun apa yang tidak kamu pahami."*
> Modeling membantu **memvisualisasikan**, **merancang**, dan **memvalidasi** sebelum membangun software yang sesungguhnya.

---

### Peran Modeling:

* **Menyederhanakan sistem kompleks** agar mudah dipahami.
* **Membantu komunikasi** antar tim (client, developer, stakeholder).
* **Menjadi blueprint** (cetakan) untuk proses pengembangan selanjutnya.
* **Mendeteksi kesalahan sejak awal**, sebelum coding dimulai.

---

## Mengapa Modeling Itu Penting dalam RPL?

| Alasan                                     | Penjelasan                                                                                           |
| ------------------------------------------ | ---------------------------------------------------------------------------------------------------- |
| ✅ **Mengurangi kesalahan sejak awal**      | Lebih murah dan cepat memperbaiki kesalahan pada tahap desain dibanding saat software sudah selesai. |
| ✅ **Dokumentasi jangka panjang**           | Model bisa dijadikan dokumentasi arsitektur software.                                                |
| ✅ **Meningkatkan kolaborasi**              | Diagram dan model mudah dipahami oleh semua pihak, termasuk non-programmer.                          |
| ✅ **Mendukung perubahan dan pemeliharaan** | Perubahan bisa dianalisis lewat model, tidak langsung ke kode sumber.                                |

---

## Contoh Bentuk Model dalam RPL

| Jenis Model                           | Tujuan                                    | Contoh                       |
| ------------------------------------- | ----------------------------------------- | ---------------------------- |
| **Use Case Diagram**                  | Mewakili interaksi pengguna dengan sistem | Login, Registrasi            |
| **Activity Diagram**                  | Proses bisnis atau alur kerja             | Alur pemesanan online        |
| **Class Diagram**                     | Struktur kelas dan relasi antar objek     | Sistem inventaris            |
| **Entity Relationship Diagram (ERD)** | Struktur dan relasi database              | Relasi user dengan transaksi |
| **Data Flow Diagram (DFD)**           | Aliran data dalam sistem                  | Sistem perbankan             |

---

## Ringkasan:

| Konsep                   | Ringkasan                                                                         |
| ------------------------ | --------------------------------------------------------------------------------- |
| **Software Engineering** | Ilmu rekayasa untuk membangun perangkat lunak secara profesional dan terstruktur. |
| **Modeling**             | Teknik untuk memvisualisasikan sistem sebelum dibangun secara nyata.              |
| **Tujuan Modeling**      | Memahami, merancang, dan mengkomunikasikan sistem dengan lebih baik.              |
